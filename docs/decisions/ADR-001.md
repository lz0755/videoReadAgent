## 1. 背景与决策范围

本 ADR 仅记录 M0.1 阶段对主候选视觉 Provider（DeepSeek OpenAI 兼容 Chat Completions 端点）的当前官方合同核验、离线边界/序列化/SDK 验证结果、显式限制与下一步路线决策，不构建任何生产业务系统。

同时记录一项经用户确认的环境偏离：
- 计划书基线为 Python 3.11；根据用户决策，当前仓库保留 **Python 3.14.6** 运行环境（`.python-version = 3.14`，`requires-python = ">=3.14"`）。已验证本阶段锁定的全部依赖（`httpx==0.28.1`、`openai==3.59.0`、`pillow==13.0.0`、`pyyaml==6.0.4`、`pytest==9.2.0`、`pytest-socket==0.8.1`、`ruff==0.17.6`、`mypy==2.4.1`、`import-linter==2.17`）在 Python 3.14.6 上可正常安装与运行。后续引入 `PyAV` 与 `faster-whisper`（M0.2 / M1.5 / M2）时需单独核验 Python 3.14 wheel 兼容性。

## 2. 当前官方合同快照（2026-11-25）

| 项目 | 官方合同事实 | 对项目实现的约束 |
| --- | --- | --- |
| 模型配置 | API ID：`deepseek-flash`（展示版本 `DeepSeek-V4.1-Flash-1017`）；`deepseek-v4-pro` 不支持视觉 | 模型 ID 作为配置文件参数（`provider_deepseek.yaml`），不硬编码；live 运行须先查 `GET /models` 并记录响应标识；别名不是不可变权重锁 |
| 支持格式 | JPEG、PNG、GIF、WebP（按文件内容探测，而非文件名/MIME） | 发送前校验真实字节格式 |
| `detail` 参数 | `low` 预缩至 `512×512`；`high`/`original`/`auto` 当前语义等价 | **即使使用 `high/original/auto`，推理前供应商仍按约 `1300×1300`（上限 `1024 tokens/图`）自动缩放；不得将 `detail="high"` 写成“小字必可读”或无损像素保证** |
| 请求体与单图上限 | 完整序列化 JSON body ≤ **48 MiB**（`50,331,648` bytes，含 base64）；单张内联/URL 图 ≤ **32 MiB**；Files `file_id` 单图 ≤ **64 MiB** | 必须测量序列化后完整请求体字节数，不只加总原始图片大小 |
| 多图数量与单边尺寸边界 | 单请求最多 600 图；`<15` 张时单边上限 `8192 px`；**`≥15` 张时单边上限降至 `4096 px`** | 与项目 P0 预算（索引单请求 8 图、QA 精看单请求 16 图）是两层独立规则；仅测普通 1080p 不能证明测到 `4096 px` 边界 |
| JSON Output | `response_format={"type":"json_object"}`，Prompt 须含 `"json"` | 官方文档明确：非 JSON 输出可能被替换为空格 `U+0020`（即使 `finish_reason="stop"`），解析器必须显式拦截纯空白内容 |
| Tool Calls 与工具图片 | Vision 文档允许在 `user`/`system`/`tool` 消息放图，`assistant` 放图报 `400`；Chat Completions 不支持会话中途伪插 tool call | 当前锁定 SDK `openai==3.59.0` 的 `ChatCompletionToolMessageParam` 静态类型仅声明文本内容块；离线 `MockTransport` 验证非类型化 dict 可在线路层保留 `tool_call_id` 与 `image_url`，但真实端点往返未实测；**P0 默认仍采用文字 JSON Observation + `evidence_id` 回传** |
| Files API | `POST/GET/DELETE /files`；`purpose="user_data"`；`expires_after[seconds]` 范围 `3600..2592000`，省略则永久留存；账户级共享 | **不在 P0 生产路径使用**；仅作授权小样本探针，强制设置短 TTL 并验证删除；`file_id` 复用仅省上传带宽，**不使推理图像 token 免费**；HTTP 请求/重试/上传字节单独计入 `provider_http_attempts` 与 `transferred_bytes`，共享 `deadline_seconds` |
| 官方错误码 | `400/401/402/408/413/422/429/500/503/504` | `401/402/403` 立即停止不换厂商；`408/429/500/503/504` 应用层最多 2 次重试且入账；SDK 重试为 0；网络超时/未知状态记 `cost_status="unknown"` 且不退回零费用 |

### 3.1 离线构造与真实基准抽样指标摘录（M0-A1 真实帧对照与 14/15/16 × 4096/4097px 边界）

1. **受控公开基准子集（M0 / M1.5 / M6，≤ 20 GB 硬上限）**：
   - 来源：`DogNeverSleep/MME-VideoOCR_Dataset`（CC-BY-NC 4.0 学术非商）、`showlab/VideoGUI` + 官方 HuggingFace `VideoGUI/*`（NeurIPS 2024 学术基准，无 OSI LICENSE 文件，仅限本地非商评测）、`MME-Benchmarks/Video-MME-v2`（公开学术评测，非再分发）。
   - 实际本地落盘体积（`data/datasets/`，已加入 `.gitignore`）：**`417,760,729` bytes（`0.4178 GB`）**，远低于 `20 GB`（`20,000,000,000` bytes）硬上限；其中通过 HTTP Range 按需抽取单个 MP4，避免下载完整的 17 GB `Video.zip` 与 105 GB `Video-MME-v2`。
   - 严格 Dev / Holdout 隔离（按 `source_group_id`、`original_id`、`source_video_url`、`task_id` 零交集校验）：
     - **M0 / D0 Dev（6 视频 + 24 张 VideoGUI 高分截图）**：`vg_ae10_start`、`vg_pr10_start`、`ocr_941`、`ocr_750`、`vmme_001`、`vmme_087`。
     - **M1.5 极简切片（3 段 Dev 视频）**：`vg_pr10_start`（9.4s，Premiere Pro）、`ocr_941`（30.0s，GUI 对话框小字）、`ocr_750`（60.0s，字幕+音轨）。
     - **D1 补充 Dev（+10 视频 → 16 Dev 视频）**：`vg_ae11_start`、`vg_cc11_start`、`ocr_905`、`ocr_903`、`ocr_1243`、`ocr_935`、`vmme_011`、`vmme_082`、`vmme_104`、`vmme_113`。
     - **M6 留出集（8 视频 + 16 张 VideoGUI 独立任务截图）**：`vg_pr18_start`、`vg_cc12_start`、`ocr_914`、`ocr_968`、`vmme_084`、`vmme_091`、`vmme_109`、`vmme_191`（答案真值单独隔离存放于未跟踪 `data/datasets/manifests/m6_holdout_private.json`，严禁用于 M0/M1.5/M4 调优）。
   - **编码与时长 `ffprobe` 核验发现**：全部 24 段视频时长均在 `5.0s–507.1s`（≤ 600s）、单文件 `0.89–36.68 MB`（≤ 500 MiB）、分辨率 ≤ 1080p；VideoGUI（6 段）与 MME-VideoOCR（8 段）均为原生 `h264`，而 Video-MME v2（10 段）为 `hevc`（H.265，本机 FFmpeg 可正常按真实 PTS 解码，M2 需同步验证 PyAV 对 HEVC 的解码支持）。

2. **M0-A1 真实抽取样本离线对照（11 个样本 / 26 张真实帧，全部 SHA-256 校验通过，含真实 `ffprobe` PTS）**：

     - 策略 A（原图 `detail="high"`，1 图）：序列化请求体 **`365,687–536,751` bytes**（但供应商内部仍约 `1300×1300` 缩放，高分界面小字存在显著缩放损失风险）。
     - 策略 B（960 概览 + 960 编号网格预览 + 无网格原图 ROI 裁剪，3 图）：序列化请求体 **`278,801–412,589` bytes**（在线路体积上反而小于单张 2560×1600 原图，且无网格原图 ROI 裁剪尺寸低于 `1300×1300` 内部缩放阈值；网格预览仅用于选区，不作为事实证据）。
   - **1920×1080 / 1280×720 真实视频帧（VideoGUI `PR_10`、MME-VideoOCR `ocr_941` [真实 `pts=15013 ms` vs 请求 `15000 ms`]、`ocr_903` 中文“寒潮”、`ocr_1243` IDE 代码）**：

3. **14/15/16 图 × 4096/4097px 边界离线验证**：
   - `14 × 4096px`（`42,571` bytes）与 `14 × 4097px`（`43,355` bytes）：允许（上限 `8192 px`）。
   - `15 × 4096px`（`45,597` bytes）与 `16 × 4096px`（`48,623` bytes）：允许（上限 `4096 px`）。
   - `15 × 4097px`（`46,437` bytes）与 `16 × 4097px`（`49,519` bytes）：**明确拒绝**（`IMAGE_DIMENSION_LIMIT_EXCEEDED`）。
   - `15 × 1920×1080`（`191,715` bytes）：允许，但 `exercises_15_img_4096_boundary=false`，显式标注 `ordinary_1080p_cannot_prove_4096px_limit`。

## 4. 限制与备选方案

### 已知限制
1. 尚未执行真实账户 live 探针，因此账户权限、实际延迟、真实 token 用量、`deepseek-flash` 小字实测辨认能力与 `U+0020` 空白 JSON 发生率均未获得实测证据。
2. `deepseek-flash` 内部缩放至约 `1300×1300`（上限 1024 tokens/图），对 2560×1600 / 1080p 高密度软件界面小字存在固有分辨率损失风险，需在 live A/B 对照中实测原图 `high` 与无网格 ROI 裁剪的质量差异。
3. 保留 Python 3.14.6 可能在 M1.5/M2 引入 `PyAV`/`faster-whisper` 时触发 wheel 兼容风险，且 Video-MME v2 样本为 `hevc`（H.265）编码，M2 需实测 PyAV 解码兼容性。
4. 本地下载公开学术基准（MME-VideoOCR CC-BY-NC 4.0、VideoGUI 学术基准、Video-MME v2）仅限本地非商评测，**不自动构成第三方云端外发授权**；向 DeepSeek 云端发送抽取帧仍须显式 M0.0 `cloud_egress_authorized: true`。

### 备选路线（触发条件）
- **替代 A（软件小字质量不达标）**：在 M0.1 live / M1.5 开发集若确认原图 `high` 无法稳定辨认小字，优先采用“960 概览 + 编号网格选区 + 无网格原图 ROI 裁剪”；仍不达标则按计划书第十节以失败数据触发 P1 OCR 或更换经授权视觉 Provider（禁止静默自动切换）。
- **替代 B（工具回传图片）**：P0 坚持默认文字 JSON Observation 回传；仅当未来明确需要且真实端点 + SDK 实测通过后才作为可选模式启用。
